# Glyph Lens — Android

Glyph Lens 是从 Dynamic Glyph iOS 识别核心迁移而来的原生 Android 应用。**0.4.1 只做 Glyph 自动识别与序列预测，仅支持 arm64。** 提供实时与省电两种模式，以及可选的“绘制完成后自动隐藏”；本轮自动停止功能已从当前范围删除。

**实时模式授权后自动识别，初始不显示悬浮窗或图标。** 当已确认前缀与唯一预测覆盖已知整组，或整组都已真实确认时，每轮自动弹出一次。开启自动隐藏后，窗口只显示可拖动的 Glyph 画布；游戏确认本轮绘制结束后自动隐藏，继续同一会话等待下一轮。通知提供“显示悬浮窗”和“停止”操作。

当前行为与验收证据见 [REALTIME_VISIBILITY.md](Docs/REALTIME_VISIBILITY.md)，工程约束与用户七条规则见 [Plan.md](Plan.md)。最终生产源码 `e0c8f9d` 精确保留 ML Kit 三个反射入口，修复 Release OCR 的构造缺失，继续启用 R8。当前核心 **236 项（3 跳过、0 失败）**、Android 单元 **102 项**、构建/Lint、新签名 APK 核验和实际签名 Release **6 项界面流程通过**；Glyph 截图人工总审已通过，main 推送和 v0.4.1 Release 发布均已完成。既有 Debug 界面 20 项、实采 7 项和尺寸矩阵因业务源码相同而复用，不声称重新运行。此前三次 CPU 观测未证实继续下降。

## 当前功能

- 首页选择实时/省电模式、开始/停止、系统屏幕共享授权、显示/隐藏悬浮窗和打开 Ingress。
- 默认实时模式在共享授权后立即后台识别，初始隐藏窗口与图标；省电模式先显示可拖动的 48dp 悬浮图标，点击后开始识别。
- 实时模式在整组结果可用时每轮自动弹出一次，按当前阵列空隙重新避让；手动通知打开保留拖动位置，离开首页不会重新打开隐藏的实时窗口。
- “绘制完成后自动隐藏”默认关闭，适用于两种模式已经启动的识别。开启后隐藏整条顶部控制行，保留可拖动的 Glyph 画布；游戏确认本轮绘制结束后自动隐藏，持续等待下一轮。
- 自动隐藏关闭时，实时 × 完全隐藏且继续识别；省电 × 停止采集、清空结果并回到图标。省电图标待命不采集、不运行 OCR。
- 通知栏的“显示悬浮窗”手动恢复最新结果；“停止”彻底结束共享。自动隐藏不会停止采集或创建新会话，旧自动停止偏好不会启用新选项。
- 实际节点/槽位定位、跨帧稳定识别、连续确认前缀预测；观察、确认和预测分别显示。
- 自动定位并标定 11 节点后复用固定采样位置；在当前像素支持的输入阶段跳过形状识别和标题 OCR，减少重复工作。
- 输入期序列冻结，保留重复项与缺槽，不把玩家笔画当作新的展示 Glyph。
- 可拖动的 Canvas 悬浮窗；实时自动弹出重新计算避让位置，手动打开保留用户位置。隐藏时停止 Canvas 渲染和过期显示刷新。
- 游戏语言自动/手动选择，画布大小、清晰度与显示设置。
- 内置形状表和序列表，可通过系统文件选择器导入替换。
- 随包 Latin、中文、日文、韩文四类 OCR 模型，安装后离线读取游戏阶段标题。

游戏结算/分数、装备与掉落、命令业务、输入正确性判断、历史统计、数据库、云同步、录像与音频、诊断导出、小组件、快捷设置、引导和演示功能已从本版范围删除，不作为未来完整移植的待办；保留本轮 Glyph 识别结果不恢复这些业务。

## 使用要求

需要 Android 10 / API 29 以上的 **arm64-v8a** 设备。安装包不包含 32 位 ARM、x86 或 x86_64 原生库；验证设备也必须能够运行 arm64 应用。

在首页选择模式和自动隐藏选项并开始，允许显示在其他应用上层，在系统共享对话框选择**共享整个屏幕**，然后打开游戏。实时模式立即后台识别并等待整组结果可用后显示；省电模式需点击悬浮图标才开始。模式和自动隐藏选项仅能在完全停止共享后修改，选择会保存。

关闭自动隐藏时，实时识别窗保留顶部控制行。点 **×** 后窗口完全隐藏且不出现图标，识别继续在原会话进行。打开前台通知，点击**显示悬浮窗**即可查看最新结果。整组结果首次可用时自动显示一次；如果本轮显示后又关闭，后续帧不会再次强行打开，下一轮仍可自动显示。自动显示会重新选择当前阵列附近的空隙；通知手动打开保留拖动位置。

开启**绘制完成后自动隐藏**后，顶部状态与 × 整行一起隐藏，只保留 Glyph 画布。窗口在绘制过程中保持显示；只有本轮已经进入输入阶段、游戏随后提供明确完成状态时才自动隐藏。短暂断帧、计时条暂时消失及刚进入输入阶段都不能当作绘制完成。新一轮开始时也清除旧窗口，等待本轮结果就绪后重新显示。隐藏后仍使用同一采集会话继续识别，不需要点击“开始识别”。

标题保持原有 350ms 有效期与既有阶段判断，自动隐藏只使用正常识别链提供的当前有效完成状态，不改变 OCR 频率、Glyph 确认或预测。Release 继续启用 R8，仅显式保留 ML Kit 实际使用的三个反射构造入口。

省电模式启动后也可使用同样的自动显示/隐藏流程；关闭该选项时保留原来的 **× 停止并回图标**，点击图标开始新识别。两种模式的首页或通知**停止**都彻底结束屏幕共享。旧版“本轮识别完成后自动停止”、静态停止结果状态与结果窗重新开始按钮已删除；旧设置不会自动开启“绘制完成后自动隐藏”。

当前识别范围为竖屏；横屏、方形、分屏及单应用共享到悬浮窗的坐标映射尚未认证。应用不需要 root、无障碍服务或麦克风。

系统共享用于当前识别，不提供录像保存、音频采集或云端上传。阶段标题中仍需区分命令/展示/输入/完成，避免在错误阶段确认 Glyph；这不等于保留命令或结果业务。

## 构建

工程为 Kotlin + Android Views/Canvas，包含 `:app` 与纯 Kotlin `:recognition` 两个模块。使用 JDK 17、仓库中的 Gradle Wrapper 和本机 Android SDK；SDK 路径放在本机 `local.properties`，不写入共享构建文件。具体依赖版本以 [版本目录](gradle/libs.versions.toml) 和 [应用构建配置](app/build.gradle.kts) 为准。

Windows 下从仓库根目录执行：

```powershell
.\gradlew.bat :recognition:test :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug :app:assembleRelease :app:lintRelease
```

Debug APK 输出到 `app/build/outputs/apk/debug/app-debug.apk`。0.4.1 使用 `versionCode = 5`，Release 启用 R8、仅打包 arm64，输出为 `app/build/outputs/apk/release/Glyph-Lens-0.4.1-arm64.apk`。当前签名包为 **15,808,043 bytes**（约 15.81MB / 15.08MiB），SHA-256 为 `d13e3f0a7dcda22c6956d0a19bf3649163d54ae58bac3e05ecfa3113b75b580c`；v3 本地测试密钥签名、ZIP/ELF 16KiB 对齐、权限和表哈希已核验。完整证据见 [0.4.1 验收与发布](Docs/REALTIME_VISIBILITY.md#5-041-验收与发布)。

本轮新增两项等价计算优化：38 条基本边使用位掩码匹配，节点和槽位连通域搜索避免对同一像素重复判色；采样位置、识别阈值、帧率与 OCR 节奏保持。此前与 3 次旧版基线匹配的模拟器观测中，进程 CPU 时间中位数为 **11.68s → 12.33s**，**未证实继续下降**，不能只选首次降低的数据。第三次在测量结束后的通知查找环节失败，不计为完整流程通过；这些值不作为当前签名包的新性能证明。原始值与限制见验收文档。隐藏实时窗口只减少显示工作，采集和识别仍持续。

识别表的换行格式由 [.gitattributes](.gitattributes) 固定，保持与已验证原始表相同的字节和哈希，避免平台切换改变打包内容。此项不修改 Glyph 或序列数据，也不放宽完整性检查。

现有测试环境为 Android 15 / API 35 的 x86_64 模拟器，经 ARM64 native bridge 执行 arm64 应用。录屏 `fitCenter` 播放只验证对应共享输出，不等同于真实游戏重新布局、所有实体机型或长期温度/电池认证。

iOS 使用系统 Vision，Android 当前选择将离线 OCR 模型随包携带。最终 0.4.1 APK 中唯一的 arm64 OCR 原生库为 **11,064,544 bytes**，另有模型、代码和资源；库解压后的大小不等于最终 APK 大小，也不能承诺与 iOS 同体积。此前的体积取舍见 [GLYPH_ONLY.md](Docs/GLYPH_ONLY.md#4-为什么仍保留离线-ocr)。
