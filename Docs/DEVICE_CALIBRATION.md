# Glyph Lens 0.4.5：设备点阵校准与槽位定位

更新日期：2026-11-09。生产源码 `e09da98`，本轮重点自动化验收和五张截图人工核对均通过，v0.4.5 已发布。

## 1. 录屏中实际失败的位置

用户提供的 `video_2026-11-09_18-41-23.mp4` 为 588×1280、约 10.47 秒，包含一枚展示 Glyph `idea`。旧实现已能匹配全部 11 个节点，拟合均方根误差约 0.26 像素，图形也能得到唯一的 `idea` 候选。

实际存在两处流程中断：

- 槽位定位过晚。未高亮的六边形约在 3.867–4.267 秒出现，默认读取区域只覆盖部分标记；旧周期搜索约 4.333 秒才重新定位，错过空白前导。在 603×1333 上下黑边场景中，标题下划线又会让默认区域持续返回标记宽度不一致，单靠“没有标记变为有标记”不足以触发重新定位。
- 地图误检。标题 `Incoming glyph sequence` 的字母局部被误认为图层按钮；603 像素采集宽度下还触发公文包按钮误检。引擎提前按地图处理，跳过了实际 Glyph 读取。

最终槽位修复依据既有扫描所得的彩色标记上下边界变化触发重新定位，不增加图像读取；静态错误区域仍保持半秒搜索节流。图层和公文包识别各增加三个实体内部探针，至少两个符合，保留既有按钮外形及其他特征。没有新增文字或语言识别。

展示空白前导、两个稳定样本、独立展示边界和预测规则保持，玩家绘制及命令图形仍不会成为已确认的展示序列。

## 2. 设备校准

首次进入 Glyph 界面，完整空白 11 点阵得到确认后，保存点阵原点、横纵尺寸和节点半径的归一化值。后续识别会话恢复这些位置，优先检查节点附近的小区域，通过当前画面确认后复用线段采样。

分辨率变化会按当前图像尺寸换算坐标。实际布局或比例改变使局部确认失败时，重新搜索点阵并更新保存值；不维护机型名单或固定屏幕像素表。保存值只是几何提示，不代替当前图像和阶段证据，不凭历史坐标直接确认 Glyph。

设置页新增校准状态与“重置识别校准”。重置清除保存值和当前引擎的校准，等待下一次空白点阵重新建立；不停止屏幕共享，不更改窗口、画布或表文件。已有自动启动、返回地图隐藏、通知控制与明确停止保持。
