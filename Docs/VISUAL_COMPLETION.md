# Glyph Lens 0.4.2：通过地图按钮自动隐藏

更新日期：2026-11-09。

**本轮按主地图的五个独立按钮判断是否隐藏悬浮窗，不识别完成页。** 开启自动隐藏后，任意一个目标按钮出现即可隐藏；这个信号只控制悬浮窗可见性，不表示游戏成功、不产生 COMPLETED，也不修改 Glyph 确认和预测。

此前奖励面板 / RESULT_PANEL 方案没有测试或发布，已经撤下。版本为 versionCode 6 / 0.4.2；全部改动落盘后的单元、界面、实采 **11/11**、两组尺寸和 CPU 对比已完成。生产源码 `6fd03bc9` 的正式签名包结构、**9 项实际界面流程与同包 9/9 人工截图核验全部通过**。main/Release/szres 同步尚待执行，不提前记录发布完成。

## 1. 五个独立目标

| 位置 | 目标 | 检测要求 |
| --- | --- | --- |
| 右侧 | 圆钮中的菱形 | 独立裁切和标定，不与下面两个按钮合成一个模板 |
| 右侧 | 圆钮中的信号弧 | 独立裁切和标定 |
| 右侧 | 圆钮中的叠层 | 独立裁切和标定 |
| 左侧 | 方框中的加号 | 独立目标 |
| 地图界面 | 公文包 | 独立目标 |

五个目标之间使用“任一出现”的关系，不要求同时找到多个，也不依赖其他按钮仍在原位置。`MapControlReader.read(ColorImage, sourceTime): Match?` 用五个独立枚举目标和各自模板处理当前画面，不读取文字或语言。

应用采集先统一缩至宽度不超过 **603px**，检测器在相对的边缘/底部区域做多尺度粗定位；缓存命中位置后逐帧用少量样本复验，未命中时全搜索最多 **4Hz**。实际图标证据见第 3 节，不将搜索上限或少量采样直接等同于已测得的 CPU 降幅。

## 2. 显隐行为

- “返回地图后自动隐藏”沿用原自动隐藏偏好键和值，默认关闭。开启时，任意一个地图目标被识别就隐藏悬浮窗；不要求此前进入 INPUT、不要求序列 frozen，不等待完成阶段或标题。
- 这个地图信号独立于游戏阶段，不把返回地图写成成功 COMPLETED，不覆盖已经确认的 Glyph，也不改变预测。
- 在地图上通过通知手动显示窗口后，只要仍检测到任一目标，就会再次自动隐藏。这是开启选项后的预期行为。
- 自动隐藏关闭时保留正常 × 与通知控制，不因地图按钮出现自动关闭窗口。
- 实时隐藏后继续同一采集会话；下一轮出现并完成原有识别/预测条件后照常显示。省电启动、图标待命及明确停止沿用现有模式规则。
- 自动隐藏开启后仍只显示可拖动的 Glyph 画布，去掉顶部 × 整行；完成页结构、文字和绘制结束延时均不是隐藏依据。

地图按钮的视觉检测不依赖游戏语言；这不代表所有识别阶段删除 OCR。其他阶段所需 OCR、语言设置、随包模型和 R8 的三个反射入口保留规则仍有效。

## 3. 实现边界

复用现有轻量 Kotlin/Views/Canvas 与 arm64 工程，不引入 OpenCV、跨平台运行时或额外推理模型。地图检测与 Glyph 的 11 节点标定、固定采样和前缀预测职责分开；新信号只控制可见性，不能借机改动 Glyph 阈值、槽位确认或预测业务。

引擎将当前地图正向命中写入快照的 `hasMapControl`，命中后提前返回，跳过形状识别、阵列搜索与标题 OCR；不改 tracker、槽位或预测，不发出 COMPLETED。上一帧地图标志参与原有节流，下一 Glyph 仍采用原采样规则。地图退出到下一轮的首图、后两图和预测必须通过实采回归，不能以降低采样换取负载数字。

当前轮实际进入 INPUT、展示序列已观察且冻结后，暂停新的标题 OCR 请求，直到下一次展示恢复。这个条件只控制 OCR 工作量，**不是地图自动隐藏的前提**；在未开始过本轮识别的地图画面，任意目标仍可触发隐藏。其他阶段保留原有标题有效期和语言配置，窗口隐藏本身不停止采集会话。

检测数据在入口完成解析和校验，内部传递明确类型；五个按钮分别标定，不能把右侧三按钮整体截图当作一个必须同时出现的目标。不为假设机型加入品牌/型号分支。用户七条规则继续见 [Plan.md](../Plan.md#2-强制通用规则)。

真实误判样本显示，仅用图标线条会把浮窗青字或灰窗当作地图，干扰后续 Glyph 采样。因此保留原图标模板，并增加图标自身的背景与颜色证据：

- 四个圆钮各采样 8 个黑底方向，至少 6 个亮度不超过 8；允许向内 1px 避开外圈。
- DIAMOND 再校验 8 个灰色底座点和真实红色指南针。
- SIGNAL/LAYERS/BRIEFCASE 的中性色通道差不超过 40；SIGNAL 的白色亮度门槛为 160。
- PLUS 作为独立目标匹配紫色框，不要求其他图标同时出现。

没有额外边缘距离、机型或阶段门槛。真实背景五个独立目标在应用的 603×1333 输入上均正确；直接输入原始 1216 宽截图时，独立 PLUS/LAYERS 的粗定位没有命中。这不是生产采集路径，不能宣称检测器在所有原尺寸输入上都已通过。最终单元负例、完整 11 项实采与两组额外尺寸矩阵通过。

## 5. CPU 实测、交付与限制

相同 Android 15 模拟器、1216×2688 输出，旧/新版本各三次**交替冷启动**；每次固定播放五图素材前 30 秒，六次均通过。计数是应用与 instrumentation 测试进程的 CPU，视频播放器在独立进程；测量包含 INPUT、结果画面及地图停留，不包含下一轮。原始汇总见 [cpu-comparison.json](../build/v042-validation/cpu-comparison.json)。
