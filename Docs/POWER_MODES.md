# Glyph Lens 0.3.0：实时、省电与本轮自动停止

更新日期：2026-11-09。

**两种模式共用 Glyph 识别与预测。省电模式把开始识别交给悬浮图标，待命时停止画面采集和 OCR；激活后的识别规则与实时模式一致。** 两种模式都可开启“本轮识别完成后自动停止”，在本组展示结束后停止识别、保留静态结果。安装包仍只支持 arm64，Release 继续使用 R8，不恢复游戏结算、装备、历史、云同步、录像等已删除功能。

加入自动停止选项后的完整版本正在统一构建与验收。此前未包含该选项的测试与包信息只对应中间构建，不作为本文件的最终验收结果。0.2.0 的包大小、哈希和尺寸矩阵保留在 [GLYPH_ONLY.md](GLYPH_ONLY.md)，仅证明对应旧版本。工程原则及用户七条原始规则见 [Plan.md](../Plan.md)。

## 1. 用户操作

| 操作 | 实时（默认） | 省电 |
| --- | --- | --- |
| 首页开始并授权共享整个屏幕 | 立即采集、识别，显示识别窗 | 显示 48dp 悬浮图标，等待点击 |
| 点击待命图标 | 开始新的识别会话 | 开始新的识别会话 |
| 拖动待命图标 | 只改变图标位置 | 只改变图标位置 |
| 点击识别窗 × | 停止识别、清空结果并回到图标 | 停止识别、清空结果并回到图标 |
| 再次点击图标 | 在原共享授权内重新开始 | 在原共享授权内重新开始 |
| 开启自动停止后，本组展示结束、进入输入阶段并冻结 | 停止采集与识别，保留静态结果窗 | 停止采集与识别，保留静态结果窗 |
| 点击保留结果窗的“开始识别” | 清空旧结果，开始新会话 | 清空旧结果，开始新会话 |
| 点击保留结果窗 × | 清空结果并回到待命图标 | 清空结果并回到待命图标 |
| 首页或通知停止 | 结束共享并移除窗口 | 结束共享并移除窗口 |

首页保存上次选择，首次使用默认实时。只在完全停止屏幕共享时允许切换模式。省电开始需要可见图标，启动时会确保悬浮窗显示设置开启；系统悬浮窗权限仍由用户授予。

首页的**本轮识别完成后自动停止**是独立选项，默认关闭，两种模式都适用。开启会确保浮窗显示，以便保留结果并提供再次开始入口。“完成”表示本组展示结束、已进入输入阶段并冻结；不要求所有 Glyph 都已确认。缺项、不确定项和预测仍按原状态保留，自动停止不能被解释为全部识别成功。

两种模式中的 × 都是**停止识别并清空结果**。图标待命或自动停止保留结果时，系统共享指示和前台通知可能仍在，因为本次共享授权仍有效；图像接收已解除，不在后台继续识别。彻底结束共享请使用首页或通知中的停止按钮，或系统自己的共享停止入口。共享一旦结束，下次开始需再次授权。

首页的显示/隐藏悬浮窗只影响可见性，不停止或启动识别。图标隐藏后可以在首页恢复显示。识别过程中仍可拖动完整悬浮窗，既有自动避让行为保持。

## 2. 图标待命与保留结果时停止的工作

本次省电的主要改动是识别工作的启停边界。识别时依然使用完整 Glyph 管线；图标待命和自动停止后保留结果都不靠低频截图轮询等待下一次操作。

| 资源或工作 | 图标待命 `STANDBY` | 保留结果 `RESULT_READY` | 识别中 |
| --- | --- | --- | --- |
| 系统共享授权 / `MediaProjection` | 保留 | 保留 | 保留 |
| 本次授权的 `VirtualDisplay` | 保留，接收面为 `null` | 保留，接收面为 `null` | 连接当前 `ImageReader` |
| `ImageReader` 与图像回调 | 关闭，无新图像采集 | 关闭，无新图像采集 | 打开，读取最新帧 |
| Glyph 引擎与 OCR 线程 | 关闭 | 关闭 | 创建并运行 |
| 识别刷新任务 | 取消 | 取消 | 按当前管线调度 |
| 显示快照 / 槽位 / 预测 | 清空，不显示旧序列 | 保留最后冻结快照，不继续更新 | 使用本次识别会话结果 |
| 悬浮窗口 | 48dp 可拖动图标 | 静态结果窗与“开始识别”按钮 | Glyph 识别窗 |
| 前台通知 | 显示待命和彻底停止入口 | 显示已停止识别和彻底停止入口 | 显示识别和停止入口 |

系统授权后先创建一个不连接图像接收面的 `VirtualDisplay`。实时模式立即连接新接收面并开始识别；省电模式保持待命。× 解除接收面、关闭 `ImageReader` 和识别引擎、停止 OCR 线程、取消刷新、清空旧快照。再次点击图标创建新的识别引擎和图像接收器，重置会话状态，防止上一轮 Glyph 或预测残留。

自动停止选项开启后，当快照进入 `INPUT` 且 `isFrozen`，服务停止采集与识别并进入 `RESULT_READY`，保留该快照用于静态显示。不会等待缺失槽位补齐，也不会把预测改成确认。结果窗“开始识别”创建新引擎和新会话、清空旧快照；结果窗 × 则清空快照并收回图标，继续保持同次授权。

同一授权只调用一次 `createVirtualDisplay()`，之后复用这个显示来连接和解除接收面。Android 14 及以上限制一次授权令牌只能创建一次显示，因此恢复时不能重新创建整个显示。依据见 [Android MediaProjection 官方说明](https://developer.android.com/media/grow/media-projection)。

官方将 [`VirtualDisplay.setSurface(null)`](https://developer.android.com/reference/android/hardware/display/VirtualDisplay#setSurface(android.view.Surface)) 描述为解除接收面、效果类似关闭显示。这能停止应用接收投射画面，但不能由此推断应用或系统完全零耗电：前台服务、通知和悬浮窗口仍存在。具体 CPU 和手机发热必须通过真实运行测量。

主要实现位置：

- [CaptureService.kt](../app/src/main/java/org/szres/glyphlens/capture/CaptureService.kt)：共享、图标待命、识别、保留结果、彻底停止及资源生命周期。
- [RecognitionMode.kt](../app/src/main/java/org/szres/glyphlens/settings/RecognitionMode.kt)：实时和省电模式值。
- [MainActivity.kt](../app/src/main/java/org/szres/glyphlens/ui/MainActivity.kt)：首页模式、自动停止选项和共享状态。
- [OverlayController.kt](../app/src/main/java/org/szres/glyphlens/overlay/OverlayController.kt)：图标点击/拖动、识别窗口及 × 操作。

## 3. 识别与预测继续对齐 iOS

本轮不改节点几何、线段匹配、跨帧稳定、确认边界、连续确认前缀预测或输入期冻结。仍先沿用 iOS 实现，以真实失败样本修正通用定位与坐标，不增加逐机型参数表。

识别激活期间，两个模式都保留：

- 在像素映射和复制前执行约 20Hz 帧准入，处理落后时读取最新帧，避免积压全屏图像。
- PRESENTING 和 INPUT 标题 OCR 正常 100ms、系统受限时 200ms；沿用 iOS 的阶段规则。该间隔是提交资格，不保证模型调用能在该时间内结束。
- 单个在途 OCR、真实源帧时间、0.35 秒标题来源年龄及 0.75 秒阶段 grace；非 hack/静止画面使用既有调度。
- 真实节点与槽位行定位、连续重复 Glyph 保留、漏槽不前移、只有唯一预测才展示确定后缀、INPUT 冻结展示序列。

**省电模式不会为了减少激活期间的工作而降低识别帧率或改变预测规则。** 两种模式的区别仍是初始授权后立即识别还是先等待点击。自动停止选项只在本组展示进入 INPUT 并冻结后结束后续采集；关闭时保留输入期冻结显示和既有采集状态，不改变正常展示期的确认边界。

点击图标或结果窗“开始识别”较晚、已经错过游戏展示的前几个 Glyph 时，新会话不会凭空恢复错过内容；建议在本组展示开始前开始识别。保留结果不等于持续监测下一组，下一组需要手动再次开始。

## 4. 平台与产物范围

当前交付目标仍为 Android 10 / API 29 及以上、`arm64-v8a`、竖屏整屏共享。横屏、方形、折叠设备横屏以及单应用共享/分屏到悬浮窗的坐标映射尚未认证；已有通用定位不等于所有 Android 设备都已验证。

工程保持 Kotlin、Android Views/Canvas、SharedPreferences 与本地 CSV。四类随包离线 OCR 模型保留，应用不需要 root、无障碍、麦克风或云端上传。模式切换不引入新的 OCR 后端或第三方电源管理框架。

包含自动停止选项的最终 0.3.0 APK 大小、SHA-256、签名、ABI 和权限需在统一构建后记录，不沿用中间构建的包信息。省电模式和自动停止没有缩减离线 OCR 模型体积。
